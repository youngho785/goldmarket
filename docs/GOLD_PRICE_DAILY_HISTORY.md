# 금시세 일별 보관과 과거 정정

- 관리 경로: 관리자 → 금시세 관리
- 오늘의 시세는 하루에 여러 번 저장할 수 있으며 날짜별 문서에는 마지막 가격이 남습니다.
- 전일 대비 기준은 어제의 최종 시세입니다. 같은 날 재저장해도 당일 직전 가격을 비교 기준으로 바꾸지 않습니다.
- 한국 시간 00:05에 오늘까지의 날짜별 기록을 채웁니다. 최근 366일 내 누락도 함께 채웁니다. 이미 저장된 기록을 자동으로 덮어쓰지 않습니다.
- 최초로 알려진 시세 이전 날짜에는 가격을 만들어 넣지 않습니다. 366일보다 오래된 누락은 별도 보정이 필요합니다.
- 가격 변동이 없으면 전날 가격으로 저장됩니다. 실제 시장에서 변동했는지는 관리자가 확인해야 합니다.

## 놓친 가격 변동 정정

1. 실제 변경일을 선택하고 당시 시세를 입력합니다. 필요하면 ‘선택 날짜 불러오기’를 먼저 사용합니다.
2. 수정 사유를 입력하고 ‘보정 미리보기’로 변경 날짜와 가격을 확인합니다.
3. ‘확인 후 보정 저장’을 누릅니다.

선택 날짜부터 다음 직접 등록일 전날까지 새 가격이 이어집니다. 다음 직접 등록일의 가격은 유지하고 그날의 전일 대비 기준만 수정합니다. 이후 직접 등록일이 없다면 오늘의 기록과 현재 공개 시세에도 반영합니다.

예: 10월 1~5일이 모두 A일 때 3일을 B로 정정하면 1~2일은 A, 3~5일은 B입니다. 5일에 직접 입력한 C가 있으면 3~4일만 B이고 5일은 C입니다.

미리보기 이후 날짜·가격 또는 저장된 기록이 달라지면 다시 미리보기해야 합니다. 기록·현재 시세·감사 이력은 한 트랜잭션으로 저장됩니다. 정정 자체는 회원 알림을 발송하거나 확정된 거래를 변경하지 않습니다.

## 연간 파일 보관

‘일별 금시세 보관 · CSV 다운로드’에서 연도를 입력하고 ‘선택 연도 전체 기간’을 누른 뒤 내려받습니다. 올해는 오늘까지만 선택됩니다. 또는 시작일과 종료일을 직접 지정할 수 있습니다(최대 366일).

CSV는 UTF-8 BOM을 포함하여 엑셀에서 열 수 있습니다. 날짜별 6종 가격(원/돈)과 직접 등록/자동 유지 구분을 포함합니다. 저장되지 않은 날짜는 빈 가격과 ‘기록 없음’으로 표시하며 임의 가격으로 채우지 않습니다. 14K 판매가 표시 설정과 관계없이 파일에는 관리자가 저장한 원본 가격이 포함됩니다.

## 배포 전 검증 및 반영

로컬 변경만으로 운영 서버의 자동 저장은 시작되지 않습니다. 프런트엔드와 아래 Functions를 함께 반영해야 합니다.

- saveDailyGoldPrice
- previewGoldPriceCorrection
- saveGoldPriceCorrection
- carryForwardDailyGoldPrice

Functions를 먼저 배포한 뒤 Hosting을 반영합니다. Android 설치본은 새 웹 자산을 포함해 별도 빌드해야 합니다. 배포 후 스케줄 생성과 최초 실행 로그를 확인해야 합니다.

단위 검사: `node --test scripts/test-daily-gold-price.mjs`

통합 검사: Functions 빌드 후, 별도로 실행한 로컬 Firestore 에뮬레이터 `127.0.0.1:8099`와 프로젝트 `demo-goldmarket` 환경에서 `node functions/scripts/test-daily-gold-price-emulator.mjs`를 실행합니다. 이 검사는 해당 에뮬레이터의 금시세 테스트 컬렉션을 초기화하므로 반드시 전용 에뮬레이터를 사용합니다. 운영 프로젝트에서는 실행을 거부합니다.
